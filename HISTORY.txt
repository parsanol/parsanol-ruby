== Parsanol 1.3.0 (unreleased)

Breaking changes:

* Simplified API: Single `parse()` method with lazy line/column
* Removed deprecated methods: `parse_parslet`, `parse_parslet_with_positions`,
  `parse_with_transform`, `parse_to_objects`, `parse_raw`
* Pure-Ruby ordered choice now follows Parslet's prefix-success cache
  semantics: a non-strict success of a choice/sequence/repetition is reused
  for a strict (consume-all) attempt at the same position. Some grammars that
  previously parsed on parsanol but fail on Parslet 2.0 now raise ParseFailed,
  matching Parslet. Strict *failures* are NOT reused for prefix attempts
  (memoization keys are scoped by parse mode), which also fixes inputs that
  previously failed only above the adaptive caching threshold.
* Error messages for choices with more than 16 alternatives now read
  "Expected one of N alternatives" instead of enumerating every branch
  (the per-branch causes remain available in the failure cause tree).
* `Slice#hash` is now consistent with `Slice#eql?` (content-based,
  offset-independent), fixing the equal-objects-equal-hash contract;
  content-equal slices at different offsets now collide as Hash/Set keys.
* `Alternative#alternatives` now returns a frozen array, so in-place mutation
  raises FrozenError (the lazily built literal index relies on immutability);
  compose new choices with `a | b` instead.

New features:

* Lazy line/column computation in `Slice#line_and_column` - computed only when accessed
* `BatchDecoder` module for efficient batch AST processing
* Grammar accepts Ruby atoms directly - no JSON serialization step needed
* Literal-prefix indexing for large ordered choices (16+ branches) on the
  pure-Ruby path; the failure-reporting pass still tries every branch so
  error cause trees stay complete
* Parser-class parses memoize at all input sizes by default
  (`PARSER_CACHE_LIMITS` `:parser_default`; the named per-grammar thresholds
  remain); thresholds are performance-only because cache-unsafe results are
  excluded from memoization (see below)

Bug fixes:

* Fixed grammar cache cycle detection to prevent stack overflow on recursive grammars
* Fixed wrapper vs repetition pattern detection in `AstTransformer`:
  - Same inner keys → Repetition pattern (keep as array)
  - Different inner keys → Wrapper pattern (merge inner hashes)
* Correct entity extraction for grammars with multiple declarations
* `dynamic {}` blocks and capture writes are never memoized: composite
  results that read or write capture state are re-evaluated on every
  attempt, at every cache threshold and regardless of the parser class name
* Repetition interval/tree memoization actually replays cached results
  (the lookup was previously unreachable) and stays consistent across
  consume-all modes
* `Buffer#clear!` clears the used slots instead of the unused tail,
  fixing a pooled-buffer reference leak

== Parsanol 1.2.0 (2026-03-07)

New features for advanced parsing scenarios:

=== Capture Atoms

Extract named values from parsed input without building full AST:

* `atom.capture(:name)` - Capture matched text by name
* Zero-copy extraction using offset/length
* Works across all backends (Packrat, Bytecode, Streaming)

=== Scope Atoms

Create isolated capture contexts for nested parsing:

* `scope { inner }` - Discards inner captures on exit
* Prevents capture pollution in recursive structures
* Memory-bounded parsing for repeated patterns

=== Dynamic Atoms

Runtime-determined parsing via FFI callbacks:

* `dynamic { |ctx| parser }` - Context-sensitive parsing
* Access captures, position, and input in callback
* Full Packrat backend support

=== Native Extension Updates

* Updated to parsanol-rs 0.3.0
* New backend abstraction (Packrat, Bytecode, Auto)
* Streaming parser with capture extraction
* Performance improvements

== Parsanol 1.1.0 (2026-03-05)

Position information is now returned by default:

* All parse methods return `Parsanol::Slice` objects
* `Slice#offset`, `#length`, `#line_and_column` methods
* Zero-copy extraction via `Slice#extract_from(input)`
* JSON output format includes position inline

Performance improvements:

* Native extension ~20x faster than pure Ruby
* ZeroCopy API for direct FFI object construction
* Parallel batch parsing with `Parsanol::Parallel`

== Parsanol 1.0.0 (2026-03-03)

Initial release of Parsanol, a high-performance PEG parser library for Ruby.

Features:

* Parslet-compatible API for easy migration
* Optional Rust native extension for 17-42x faster parsing
* Static frozen parsers for thread-safe operation
* Dynamic parsers for mutable grammars
* Great error reporting with source location tracking
* Packrat memoization for O(n) parsing complexity
